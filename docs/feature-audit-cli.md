# Unified CLI configuration evidence

Alex explicitly requested implementation of full local/registered-remote CLI configuration, including MCode-only, without changing real provider/account/remote state. This expands the existing Agent settings and shortcuts feature, not model capabilities. Implementation remains unreleased in this branch.

The audit maps 179 core methods, 19 service methods and all 75 Settings fields in [cli-coverage.md](cli-coverage.md). [cli.md](cli.md) documents exact target selection, expected-value semantics, MCode-only dependency changes and native boundaries. Shared dispatcher: `core/product-cli.ts`, `product-sessions.ts`, `product-shortcuts.ts`; target selector: `cli/computer.ts`; remote: `service/remote/computers.ts`; Manager source auth/confirmation: `main/manager-operations.ts` and `manager.ts`; provider guards: `main/provider-settings.ts`, `main/sessions/index.ts`.

Synthetic checks cover expected-value conflicts, unknown/ambiguous host refusal, no fallback, alias compatibility, protected current work, disabled provider selection, operator bearer failure, observation scope denial, Manager authority after connection, lost source replies and secret input refusal. Actual built CLI integration uses two isolated localhost Node services and encrypted WebRTC with local signaling. Test model plugins are fixtures, not real MCode or any authenticated account. Physical remote, NAT/TURN/Firebase, native interactive authorization and real model accounts were not exercised. Exact final results are in [verification.md](../specs/026-unified-host-cli/verification.md).
