# GeckIt features

Combined product feature list agreed with Alex on 2026-10-04. Describe what GeckIt adds to the workflow; model reasoning, coding and tool execution belong to the underlying assistants. Supporting evidence and implementation details are in [the feature audit](feature-audit.md).

## Desktop and work management

- **One configuration file.** In the working tree, keep preferences, assistants, projects, hosts, saved shortcuts, phrases, employees and Manager configuration in one versioned `settings.json` with named sections. Existing files migrate automatically with private backups. Desktop Settings > General > Configuration reveals the file and offers export/import. Import validates the file, requires idle work, asks for confirmation, keeps a backup and restarts GeckIt; device pairing, credentials, conversations and execution history remain local. Project paths and provider libraries must be available on the destination. Not released.

- **Agent settings and shortcuts.** In the working tree, workers and authenticated Manager read supported preferences through `settings schema` and `settings show`, and apply validated partial updates through `settings edit --patch` without an additional GeckIt confirmation. Arrays replace their named setting, maps merge entries, and optional expected values reject stale writes. Saved task and Manager prompts use the existing `employees shortcuts` and `employees shortcut` commands without an extra Allow card. Changes use the same persistent settings and shortcut handlers as the app. Provider enable/install, credentials, access grants and native permission decisions remain outside this preference interface. Isolated host/CLI integration verified persistence after restart and execution of changed prompts; installed runtime and rendered desktop/phone review remain unverified. Not released. In this working tree, ordinary CLI commands also target an already registered full-control GeckIt computer with `--host <id>` (`--computer` remains compatible), using target capabilities and validated settings/provider/project/employee/shortcut/session/SSH-host/channel/Manager/device commands. Assistant disable checks explicit expected values, selected dependencies and current work; library installation does not enable it. Native authentication and permissions remain user-controlled; unknown or unavailable targets never fall back locally. Verified with disposable localhost RPC/WebRTC services and synthetic providers; physical remote/NAT/TURN and real model accounts remain unverified. Not released.

- **Headless service.** In the working tree, run GeckIt as a standalone Node service without a graphical session. Desktop and the local operator CLI use the same service and persistent state: conversations, approvals, settings, Manager, employees and shortcuts. Closing desktop leaves service tasks running; reopening reconnects to their state. Existing Telegram, SSH, schedules and other core workflows run in the service; native capture and phone WebRTC use desktop. Slack and colleague access are not implemented. Not released.
- **Kanban for AI sessions.** Conversations are tasks on one board across folders: In progress, In review and Done, with working, waiting and blocked states. Open a card to continue the conversation; move, reorder, favorite, hide or manage several cards together. List view is available too.
- **Multiple AI providers.** Codex and Claude Code sessions share the same workspace. Install independent assistant libraries from GitHub in Settings > Libraries, enable them in Assistants and select them for new conversations. Compare each enabled assistant's account and usage in Settings > Assistants > Account and limits on desktop and phone. In the working tree, phone account limits appear only in Settings; desktop keeps its status summary. v1.83.0 shows usage in the desktop status bar and phone Tasks disclosure. Libraries support automatic updates and removal. Settings shows load errors and can reinstall the latest copy from its GitHub source when available; released to the Development channel in v1.83.0; not promoted to Stable. In the working tree, inspect local rotating logs for each library to audit actual usage checks, cached responses and operation outcomes; plugin logging is not yet released.
- **Remote AI over SSH.** Manage conversations on remote computers alongside local sessions on one board, using existing SSH configuration, agent and jump hosts. Builtin remote execution currently supports Claude Code; builtin Codex runs locally.
- **Remote work survives disconnection.** Jobs on SSH hosts keep running when the laptop sleeps or loses its connection. GeckIt catches up when it reconnects.
- **Goals and review.** Set, view and edit a task's completion condition, follow it on the board and see completed work move to In review. The assistant executes the goal; GeckIt connects it to the task workflow.
- **Employees and conversation memory.** In the working tree, create named employees with roles, instructions and human portraits; assign them to new or existing tasks, see the assigned portrait at the bottom right of task cards, and filter work by employee on desktop and phone. Read an employee's currently assigned conversation history, including accessible hidden and finished chats, with sources and explicit availability. The employee card and Team show the employee's assigned tasks grouped by board column with a count summary and a live "working" mark; a task opens from there. Employees live on a Team page opened from the top bar: a roster with open-task counts and a live mark, and each employee's shortcuts, tasks, rules and conversations. A card's portrait is a menu that assigns or changes the employee, and an open conversation shows the employee as one chip with the same menu. Shortcuts can belong to an employee: each run starts a task assigned to them, archiving pauses their timetables and restoring resumes them without catching up, and the shortcut list and menu bar group shortcuts by employee. Desktop and phone Shortcuts rows show the assigned portrait and name; unassigned rows stay quiet and unresolved assignments say "Employee unavailable". The `geckit employees` CLI creates, edits, archives and assigns employees and adds, edits, pauses, runs and gives shortcuts; in the working tree, saved-shortcut changes apply without additional GeckIt confirmation, while employee catalog and assignment changes retain Allow in the requesting conversation. Builtin assistant instructions explain how to request assignment and memory; role/history are not automatically appended to each task message. Manager can assign an employee when delegating. In the working tree, its authenticated CLI reads and edits user instructions and employee names with expected-value checks and readback; instruction writes need no additional product confirmation, while employee name changes retain it; new delegations accept an explicit validated model without changing running sessions. Catalog editing is on desktop. Source development mode updates isolated Claude and Codex guides without editing the installed app's instructions. Live model recall, a real paired phone and SSH memory access remain unverified. Not released.
- **Work orchestration.** Queue follow-up messages, drag to reorder them on desktop or phone, edit or cancel them, limit simultaneous conversations and use board order to prioritize waiting work. Use "Send now" to deliver a selected queued message into active work on desktop or phone with builtin Codex, builtin Claude or a supporting library; failed delivery keeps the message queued. Delegate a queued message into another conversation or review new tasks requested by an assistant. Message reordering and Send now are available on the Development channel in v1.83.0. The external Claude tmux library needs its updated driver. In the working tree, Manager can explicitly steer a correction into a supporting working runtime through `sessions steer`, while ordinary `sessions send` retains the follow-up queue. Receipts distinguish host acceptance, queueing, native runtime acceptance and blocked/failed attempts; runtime acceptance does not promise immediate model application. Built-in Manager instructions in the working tree require checking a conversation's latest request before continuing it for the same task; independent tasks get separate conversations while employees retain their identity and assigned history. This is instruction-based routing, not a host-enforced guarantee of task similarity; live model routing remains unverified. Not released.
- **Chat with Manager.** In the working tree, talk to the same Manager from its portrait in the desktop top bar, the status bar or Team, and from Tasks or Team on the paired phone. Send text, follow shared history and queued requests, and answer current questions and supported native approvals. Drafts survive closing and reloading; uncertain sends check the host receipt before retrying. Telegram is optional, including during setup, and talks to Manager in a thread of its own; it is connected in Settings > Channels. The phone uses its paired computer and its permission and VPN checks. App attachments are not included. Local runtime tests and renderer fixtures passed; live provider, Telegram and physical-device integration remain unverified. Not released.
- **Manager threads and channel labels.** In the working tree, Manager keeps one conversation per place: GeckIt's Manager chat, each Telegram chat and each Slack thread, each answered in its own place while all share Manager's settings, decisions and managed conversations. Exactly one thread tracks a piece of work and gets its updates, at first the thread that started it; another thread can follow it on request only after the tracking thread unfollows it. Asked to keep an eye on an existing task, Manager attaches, follows or unfollows it without a confirmation card. Channels label threads and the conversations they start (who started it, thread id, link); labels show on the board card and phone conversation info and are found by Search. Telegram and Slack are built in and set up in Settings > Channels. Mentioning the Slack bot anywhere in a thread, including one that began without it, opens one Manager thread for that Slack thread and sends Manager what was written there first; later Manager answers only a mention, which brings what was said since, including replies that did not mention it; a reply with an open question's choice still answers it, and people outside the allow list are read but never answered unless they mention the bot. The Manager chat lists the threads beside the transcript on the computer and in a menu on the phone; a channel thread shows its place, labels and link, its Work (the conversations it tracks, each opening in Chat), and can be written into, Manager's answer going to that channel. While the work a Telegram chat or Slack thread tracks runs and Manager is not answering there, one status message at the bottom says each task's state, where it stands and its running background jobs, or that Manager waits for an answer or stopped; it is edited in place, goes away while Manager takes a message, comes back below Manager's answer, and ends with how it finished, never naming commands or other conversations' tasks. Live Slack and Telegram are unverified. Not released.
- **Discord channel.** In the working tree, Discord comes with GeckIt beside Telegram and Slack. Settings > Channels > Discord walks through four steps: connect the bot (token checked with Discord and sealed, a warning when Message Content Intent is off), add it to a server and choose every channel or only chosen ones plus direct messages, list the people allowed by Discord user ID with their names checked, and allow Manager. Mentioning the bot in a channel starts a Discord thread on that message; each Discord thread and direct message is its own Manager thread, answered in place with mentions off, with the same status message as Slack. Questions show buttons that only allowed people can press, only on that message and thread and only while open; typed values still work. Files are named to Manager, not passed. Reconnects resume and repeated events reach Manager once; fatal refusals stop with the fix. Live Discord is unverified. Not released.
- **Open what Manager names, from Telegram.** In the working tree, when a Manager message in the paired Telegram bot names a localhost address or a file or folder on this computer, those words arrive as a link. It opens only that site, file or folder, on another phone or computer, for 12 hours while GeckIt stays open. Hidden files, keys, the home folder and ~/Library are never shared, and what cannot be shared arrives as plain text with nothing said about it. At most twenty links are live at once; a new one ends the oldest. End a link with /links in Telegram or Settings > Channels > Telegram. WebSocket and hot reload traffic do not cross.
- **Scheduled work.** Save prompts as shortcuts, including their folder, goal and assistant settings. Run them manually or on daily, weekday, weekly or cron schedules while GeckIt is open. In the working tree, configure a random start window through the shortcut editor or `employees shortcut add|edit --start-window-minutes <N|none>`; the CLI lists the saved window and applies shortcut changes without additional GeckIt confirmation.
- **Manager shortcuts.** In the working tree, choose Manager as a shortcut target on desktop or phone, or through the employee CLI. Run a saved request manually or on an explicitly chosen timetable, including cron; requests enter the configured Manager and keep its assistant and approvals. Manager shortcuts appear separately from employee tasks. The former automatic Voice Memos intake is removed; existing recordings, intake history, baselines and notes are preserved, and no replacement schedule is enabled automatically. Live recording processing remains unverified. Not released.
- **Desktop gecko.** A gecko floats on the desktop, always on top, showing whether Claude is working, a conversation is waiting (with a count), or a card just reached In review; waiting falls asleep after 5 minutes alone. Pressing it opens a menu: Screenshot, New task, Voice task (spoken words, heard on this computer, open New task), the waiting conversation, Open GeckIt and Hide. Files dropped on it start a new task or go to the waiting conversation. Drag it anywhere, resize it from its corner, and show or hide it from Settings or the menu bar. macOS menu bar icon follows the same state; Screenshot is macOS only. On the `feat/gecko-character` branch; not released.
- **Screen recording to task.** Show a problem and narrate it; turn the words, frames and video into a question or task with context. Capture screenshots into tasks and questions too.
- **Cross-session search and profiles.** Find past decisions across conversations without remembering their folder. Separate work and personal folders with profiles.
- **Export a conversation and continue with another model.** In the working tree, save the available conversation as GeckIt Markdown with source details, a context overview, messages, tool results and recorded images or attachment references. On desktop or phone, select an enabled assistant and model, including across providers, and choose Copy without sending to prepare a separate chat in the same folder. Its editable first message and model choice survive reopening and app restart; copying adds no message and starts no model work. Press Send when ready, or choose Create and send for an immediate continuation. SSH preparation uploads the export to the host; builtin Codex remains local-only. Original work and queues stay in place. Earlier compacted content and unavailable files cannot be recovered; the overview is assembled from metadata and excerpts. Local builtin Codex integration passed; actual renderer desktop/phone light/dark interactions were checked with synthetic boundaries. Some UI checks, other live providers and SSH verification remain pending. Not released.
- **Recovery and attention.** Identify and continue sessions interrupted by closing GeckIt; retain pending messages. Receive notifications when work finishes or needs an answer. In the working tree, Try again appears after session errors, preserving known unsent work and continuing turns that already started. Manager automatically recovers ordinary turn failures with a capped retry delay, including saved errors after restart, and reconciles current work before queued requests without replaying interrupted commands. Manager also rechecks temporary public-IP lookup failures and address mismatches, continuing held work only after current verification passes. Uncertain CLI delivery recovers coordination automatically, including old saved delivery pauses; recorded receipts prevent repeated actions, and uncertainty holds only the affected upload while other work continues. Explicit pauses, approvals and configuration/hook blocks still require attention; unapproved VPN IPs remain blocked until a later check passes. Manager can deliberately retry a managed worker through `sessions retry`, using the same guarded recovery as Try again in the app; list/show and worker updates identify the current attempt separately from historical command results.
- **VPN IP check.** In the working tree, configure a separate Settings tab with approved public VPN IPs. Before starting or continuing session work, GeckIt checks this computer's public IP and blocks mismatches or failed verification. Retain pending work and retry deliberately with Try again. Phone requests use the paired computer's rule. While enabled, check every 10 seconds while sessions are active; failed verification interrupts supported work and holds queues until retry. Ordinary sessions require manual retry; Manager automatically rechecks temporary lookup failures and address mismatches while keeping unapproved addresses blocked. In the working tree, retry failed lookups with independent fallback services within ten seconds and keep local failure/recovery diagnostics; a verified unapproved IP still blocks immediately. SSH-host egress is not verified, and polling cannot prevent traffic between checks.
- **Voice workflows.** Speak commands to start, message, stop or mark work, with a review before execution. Dictate directly into conversations or other applications; import audio and retain transcription history.
- **Selected-text correction.** Correct grammar, improve, translate or explain text selected in another application, then copy the result or restore the original.
- **Reusable phrases.** Keep frequent instructions and add them to follow-up messages without retyping.
- **Chrome without an extension prompt.** Chrome through GeckIt is on by default and can be turned off in Settings > Integrations; while it is on, Codex and Claude conversations work in the person's own Chrome, in the tabs they are signed in to, through the GeckIt Browser extension, loaded once with Load unpacked. Settings shows whether Chrome is connected and how far the search model's download has come, and turning the switch off removes the bridge and the Chrome part of the assistants' instructions. Nothing to allow per action. A small model on this computer finds the element asked for, so only the matching lines reach the conversation, and a pointer on the page shows where the conversation clicks and types. For design work the conversation can also picture one element at full resolution, hover it, read its computed style, see the page at another window size, as a phone, in dark or light and with reduced motion, and record an animation that an action starts, slowed down if needed, as one sheet of frames with their times and a GIF. With several Chrome profiles, the conversation sees which have the extension and are open, picks the one signed in to the account the task needs or the one used last, asks when it matters, and can open a closed profile; each command reaches the profile that owns its tab. While the switch is on, GeckIt's guides tell Claude and Codex to do every Chrome task this way, and the how comes as a skill they load only when needed. Pressing the GeckIt Browser button in Chrome shows whether it is connected to GeckIt, what a conversation is doing at that moment, every tab it read or acted in with the last thing done there (one click goes to the tab, Reset undoes a changed view), the last 30 actions with any failure, and a switch that pauses GeckIt in Chrome so every request is refused until it is turned back on. macOS and Linux. The extension and the switch are on main; the panel is in the working tree.
- **Test browsers.** Besides your own Chrome, a conversation can work in Camoufox that GeckIt installs without bundled fonts and drives itself, with profiles kept by name (`geckit:<name>`) so sign-ins stay for next time. Settings > Web Browser supports creating profiles, Open, person-controlled Sign in, editing descriptions, renaming closed profiles and Delete, with download and installation progress. Since Stable v1.236.0, when browser access is enabled, GeckIt prepares Camoufox in the background at service startup or when access is turned on, without opening Settings or launching a browser window. Existing Chrome test-profile data is preserved separately and needs a fresh sign-in in Camoufox. Camoufox uses Firefox and cannot open `chrome://` or Chrome extension pages. On main; macOS ARM64 verified, Intel Mac, Linux and Windows runtime checks pending.
- **Signed-in test browsers on any computer.** An assistant can create a named test browser profile for one account, with a note saying which account, on this computer or a paired one. It gives you a one-time link that opens in GeckIt on your phone or Mac and shows that browser live, so you sign in yourself. Assistants can run any `geckit` command on a paired computer with `--computer <name>`. Released to the Development channel in v1.188.0; not promoted to Stable.
- **Remember Computer Use app access.** In the working tree, choose "Allow for this session" on a recognized Codex app-access confirmation on desktop or phone. Identical requests continue automatically within that live conversation. Stop, disconnect, driver replacement or app restart clears the choice; other apps and conversations require their own approval.

- **Telegram replies and attachments.** In the working tree, send photos and document files with captions to Manager in the paired private bot chat, and receive explicitly selected deliverables from managed local workers as photos or downloadable files. Supported images use native assistant input; other files use local file tools. Replies retain saved Manager message text and known managed-task context, including earlier messages and after restart. Unknown or unauthorized references request a fresh instruction; files cannot answer native approvals. Attachment cache has size and retention limits; SSH file transfer is unavailable. In the working tree, choose a team forum topic with a one-time command and local confirmation. Named participants share a separate Manager queue; replies and native images retain their source across queue reconstruction. Explicit approvers require verified membership. Team tools enforce worker ownership; global controls, personal history and other channels remain owner-only in GeckIt. Reconnecting creates a new generation. Offline fixtures pass; live Telegram and packaged acceptance remain unverified. Not released.

## iPhone app

- **Encrypted P2P connection.** Pair by QR code and connect to the computer over WebRTC. Use a direct connection when possible, with an encrypted relay fallback when required.
- **Remote Kanban and conversations.** Access the board away from the desk, follow work across folders and providers, start tasks, reply and stop work. Remote access requires the paired computer and GeckIt to be online.
- **AI approvals from the phone.** Answer permission requests, questions and proposed task handoffs without returning to the computer.
- **Computer control for manual actions.** View the Mac screen and use the phone as a trackpad and keyboard to handle browser buttons, system dialogs and other actions requiring a person. Pointer and keyboard control currently supports macOS.
- **Computer localhost access.** Open development pages in the phone app through the paired computer, including SSH-forwarded host pages. WebSocket and hot reload traffic do not cross this bridge.
- **Computer file access.** Open files and folders linked in conversations, read from the paired computer or an SSH host.
- **Work management and notifications.** Search conversations, switch profiles, manage shortcuts and schedules, edit goals, and receive push notices when attention is needed.
