# UX: Headless service

## 1. Зачем
Запускать GeckIt на машине без экрана и управлять работой из отдельных CLI-команд. Сервис владеет данными и выполнением задач; desktop и CLI подключаются к нему независимо. Закрытие desktop не останавливает принятые задачи.

### Путь до результата
Оператор собирает сервис, выбирает отдельный каталог данных, запускает процесс, проверяет status, добавляет проект, настраивает VPN и отдельно авторизует provider CLI под тем же системным пользователем. Затем отправляет задачу и читает результат другой командой. Готовность сервиса означает готовность принимать команды, а не наличие авторизации провайдера. Команды независимы; мастер настройки не нужен. После отключения терминала системная служба продолжает работу. Настройки и история сохраняются; после сбоя оператор проверяет состояние и явно повторяет незавершённую работу.

## 2. Что добавляется
| Поверхность | Что появляется | Когда видно |
| --- | --- | --- |
| Node service | Запуск с каталогом данных, ready/error в журнале | Запуск |
| CLI service | status, settings, projects, sessions, Manager, employees, shortcuts | Явная команда |
| Desktop | Клиент отдельного сервиса, прежний интерфейс | Обычный запуск |

## 3. Состояния
| Состояние | Когда | Текст | Действие |
| --- | --- | --- | --- |
| Ready | Socket слушает | "GeckIt service ready." | Отправить команду |
| Running | Есть активные задачи | JSON status и сессии | Смотреть результат или остановить |
| Pending | Provider просит подтверждение | Исходная карточка в pending/items | Явно ответить на конкретный request |
| Busy directory | Другой владелец | "GeckIt is already running for this data directory." | Подключиться к нему |
| Unavailable | Нет socket | "GeckIt service is not running for this data directory." | Запустить сервис |
| Rejected | Нет operator credential | "Operator access denied." | Использовать операторский CLI вне сессии ассистента |
| Failed | Ошибка настройки/provider/VPN | Исходная причина | Исправить и retry |
| Stopping | SIGINT/SIGTERM | "GeckIt service stopped." после очистки | Запустить снова при необходимости |

## 4. Переходы
| Из | Событие | В | Что видит пользователь |
| --- | --- | --- | --- |
| Stopped | Запуск завершён, автоматически | Ready | Ready и каталог |
| Ready | Оператор отправил задачу | Working | ID сессии |
| Working | Provider вернул результат, автоматически | Ready | Результат через items |
| Working | Provider запросил разрешение, автоматически | Pending | Исходная карточка |
| Pending | Оператор ответил на конкретную карточку | Working/Failed | Результат существующей проверки |
| Любое | Отключился CLI | То же | Ничего; работа продолжается |
| Ready/Working/Pending | SIGINT/SIGTERM | Stopped | Stopped после очистки |
| Stopped | Повторный запуск | Ready | Сохранённые настройки/история |

## 5. Что молчит
Закрытие клиента, внутренние тики расписания и изменения без результата не создают пользовательских уведомлений. Сервис не пытается открыть окно или принять разрешение самостоятельно.

## 6. Пороги и время
Опрос расписаний сохраняет существующий интервал 20 секунд. CLI ограничивает ожидание ответа, чтобы сломанное соединение не удерживало терминал бесконечно; после неопределённого исхода мутация автоматически не повторяется. Локальный protocol ограничивает размер запроса, чтобы незавершённый ввод не заполнял память.

## 7. Формулировки
Дословные тексты состояний приведены в разделе 3. Ошибки провайдера и VPN сохраняют исходную причину; готовность сервиса не обещает готовность внешнего аккаунта.

## 8. Краевые случаи
Пустой список — пустой JSON-массив. Второй процесс не удаляет действующий socket. После сбоя оператор проверяет PID и отсутствие владельца перед ручной очисткой устаревшего lock/socket; автоматической очистки нет. Потеря ответа требует проверки состояния; нет автоматического повторного submit. Обычный `geckit start` от ассистента сохраняет подтверждение, а operator CLI отделён. Перезапуск не превращает старые pending в разрешённые. Недоступная системная функция явно отклоняется.

## 9. Чего намеренно нет
Slack, перенос конфигурации между коллегами, общий доступ и удалённый TCP API — отдельные продуктовые функции. Нет экранного/микрофонного захвата, системных диалогов и незаметного хранения секретов открытым текстом.

## 10. Развилки
Выбран foreground Node process под системным менеджером служб: диагностика и рестарт принадлежат ОС. Скрытый Electron/Xvfb отклонён, поскольку требует графического runtime. Desktop подключается к отдельному сервису; GUI больше не владеет runtime.

## 11. Сверка с требованиями
FR-001/002: запуск и владение; FR-003/004: независимые CLI-команды; FR-005/006: общее ядро и существующие approvals; FR-007/008: остановка, сохранение и run guide. Desktop использует прежнюю компоновку и уведомления; глобальные ошибки проверяются в светлой и тёмной темах, с клавиатурой и в phone. Авторизация реализации — "Сделай это, выдели"; отдельное утверждение нового визуального дизайна не заявляется.

## Дополнение: полный клиент desktop
Обычный запуск сам подключается к работающему сервису с тем же каталогом данных или запускает отдельный процесс из своей сборки. Пользователь открывает прежний Chat и работает с теми же задачами, что доступны CLI. Закрытие окон и Quit завершают только desktop: принятые задачи, Telegram и расписания продолжаются. Остановка всего ядра выполняется явной командой `geckit service shutdown`.

| Из | Событие | В | Что видит пользователь |
| --- | --- | --- | --- |
| Нет клиента | Запустили desktop | Подключён | Прежний Chat с актуальными данными |
| Нет сервиса | Desktop не нашёл endpoint | Запуск | Окно открывается после готовности сервиса |
| Подключён | Закрыли desktop | Нет клиента | Ничего; задачи продолжаются |
| Подключён | Сервис отключился | Переподключение | "GeckIt service disconnected. Reconnecting..." остаётся до закрытия пользователем или восстановления связи; команды отклоняются до подключения |
| Переподключение | Сервис снова доступен, автоматически | Подключён | Уведомление отключения исчезает; актуальные настройки и задачи; отправленные команды не повторяются |
| Запуск | Сервис сообщил ошибку | Ошибка | "Could not connect to GeckIt service" с исходной причиной; повторный запуск после исправления |

Во время переподключения сохраняются окна и черновики. Клиент получает полный snapshot при подключении и обновления после него. Технические события без результата молчат. Native действия, которым нужен desktop, явно недоступны без него; они не имитируются на сервере. Ключи не передаются в renderer или provider environment. Полное выделение прямо авторизовано последним поручением; отдельное подтверждение неизменённой компоновки не требуется.

Ошибка сервиса — глобальное уведомление: она видна при любом выбранном провайдере, нажатие не открывает разговор. Оно закрывается кнопкой Dismiss; на phone также сохраняется смахивание. Глобальные уведомления не исчезают по таймеру. Существующее событие `chat:notice` с пустым `session` обозначает глобальное уведомление; пустой `title` удаляет уведомление с тем же `session`, не добавляя нового. Успешное подключение удаляет глобальное уведомление.
