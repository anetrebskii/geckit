# Data model: Test browser that looks like a real person

All files live under GeckIt's Camoufox folder, `~/.geckit/camoufox/` (`testingFolder()`), written atomically (temporary file, then rename) with mode 0600.

## Desktop identity

`~/.geckit/camoufox/device.json`. Exists only on a Linux server (Linux without `DISPLAY` and `WAYLAND_DISPLAY`). Made once, at the first test browser start on that server; never regenerated by GeckIt.

| Field | Type | Rule |
|---|---|---|
| `version` | `1` | Format version. |
| `base` | `"ubuntu-intel"` | Which captured profile in `client/src/cli/desktop/` it was made from. |
| `made` | ISO date | When it was made. |
| `screen` | `{ width, height }` | One of the listed common sizes. Also the Xvfb screen size. |
| `cores` | `4 \| 8 \| 12 \| 16` | `navigator.hardwareConcurrency`, weighted as Linux desktops report it. |
| `language` | BCP 47 tag | From the server's `LANG`, `en-US` when unset or `C`/`POSIX`. |
| `timezone` | IANA name | From the server's settings. The person may edit it. |

Validation: a file that does not parse or misses a field stops the browser from starting with the message in [contracts/cli.md](contracts/cli.md); GeckIt never replaces it on its own.

The values that do not vary (WebGL, voices, media devices, fonts, `navigator` strings) are read from the base profile at each start, so a GeckIt update that fixes the base reaches every server.

## Profile presentation

`~/.geckit/camoufox/presentation.json`, Linux server only.

```json
{ "version": 1, "profiles": { "zabookni": "previous", "project-geckit-b07534713cee203b": "desktop" } }
```

| State | Meaning |
|---|---|
| `previous` | Launched as before this feature: no desktop identity values (still headed in Xvfb and with uBlock Origin). |
| `desktop` | Launched with the desktop identity. |

Transitions:

- First start of the new version on a server: every existing profile folder gets `previous`.
- `profiles create` on a server, or a profile with no entry: `desktop`.
- `profiles device <name> --desktop`: `previous` to `desktop`. There is no way back, since the old values were never stored; the command says so.
- `profiles import` on a server: `desktop`, since an imported profile is a new device for the server anyway.

## uBlock Origin

Nothing is stored. Camoufox ships uBlock Origin 1.75.0 unpacked in its own program folder (`addons/UBO`), so it comes with the Camoufox GeckIt already downloads and is updated with it. Camoufox installs it as a temporary add-on when its first window opens, so it never appears in the profile's `extensions.json`; its filter lists are kept in the profile's extension storage.

## Fonts (server only)

Nothing is downloaded. At each start the server's installed families (`fc-list : family`) are intersected with the base profile's Linux catalogue and handed over as `fonts`. Installing `fonts-dejavu-core`, `fonts-liberation` and `fonts-noto-core` brings a server closer to a desktop.

## Ref registry (in the page, not on disk)

Per document, in Camoufox's isolated world: `Map<ref, WeakRef<Element>>`, `WeakMap<Element, ref>` and a `WeakSet<Element>` of secret fields. Cleared by navigation, as attribute refs are today.
