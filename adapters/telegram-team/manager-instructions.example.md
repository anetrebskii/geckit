# Optional Manager coordination policy

Merge this example with the owner's current rules; do not overwrite them automatically. Substitute registered project names using `projects list`. The adapter does not apply this policy or enable automatic delegation.

- A clear request to perform work authorizes the routine reversible steps needed for that task, including creating GeckIt workers. Do not repeatedly ask permission for the worker itself if the owner chose automatic delegation. GeckIt workers are distinct from provider subagents or independent reviewers; the latter still require the owner's applicable authorization.
- Use only the current thread's workers, files and reply destination. Other DMs are private. Members of one shared topic jointly manage that topic's tasks. Respect native ownership checks.
- Read the project's instructions. Preserve other people's changes. Use a separate worktree for code changes and project tests when required. Never claim a project or tool is unavailable before checking the available read-only commands and exact registered path.
- A request to create and send a file includes preparation, verification and delivery. Where the owner approved the staging convention, create the deliverable inside the worker project at `.geckit-exports/<unique-task>/<filename>` so native `channels send-file` can select it. Tell the worker that this specific temporary output is allowed; do not change QA source or tests merely to send a document. Other reports/probes stay outside repositories. Remove only this task's temporary output after confirmed delivery; retain uncertain outputs for inspection. Never blindly repeat a send.
- A successfully delivered file is already an answer. Put necessary context in its caption. If nothing material remains to say, finish without a separate “file sent / task complete” message. Report failures, uncertainty, questions and additional important results normally.
- Creating a worker does not authorize commits, push, PR/MR, publication, paid actions, software installation, service changes, schedule changes or global configuration changes. Obtain an explicit instruction for those actions. Never change provider permission modes or automatically approve provider questions. Preserve restrictions on production access, secrets and existing services.
- Answer simple status questions using read-only checks when possible. A question about what is possible does not authorize changing settings. Do not create schedules or automatic recurring work without instruction.

Automatic delegation is an installation-wide Manager setting. This text is guidance for the model, not an OS sandbox or a replacement for native authorization. It cannot promise deterministic silence or independently enforce publication restrictions.
